# Memory Lab

## ワンクリック全自動（実Teamsを使わない再現負荷）

「全自動デスクトップ（資料生成・PDF検索・模擬会議）」を選んで「全自動テストを開始」。Excel・PowerPointデスクトップ版が必要です。資料ファイルや会議URLの入力は不要です。

1. 10万行の数式入りExcel、1920×1080の画像24枚入りPowerPoint、24ページのPDFを2ファイル生成します。
2. Excelの再計算・並べ替えとPowerPoint編集・保存を反復します。
3. 専用SumatraPDFで2つのPDFを開き、15秒ごとに読み直して検索コマンドを実行します。検索語はMemory / Reportを交互に使用します。検索要求数を記録しますが、ヒット数・検索完了時間の自動検証はしません。連続して開いたまま検索する条件とは異なります。
4. ブラウザー2タブで動画・地図再検索・ローカルWebRTC模擬会議を同時実行します。実Teamsへの参加、実マイク・カメラ、実画面共有、外部ネットワークは使いません。実Teamsと同等の負荷とは断定できません。
5. 約10分後に専用アプリを終了し、CSV・操作ログを保存します。空きメモリ下限・緊急停止も有効です。Officeの終了は実行中の操作が戻るまで待つ場合があります。

PDFリーダーは初回に[SumatraPDF公式配布](https://www.sumatrapdfreader.org/downloadafter)から3.6.1 x64ポータブル版を `.tools` にダウンロードし、固定SHA-256で検証します（初回はインターネット接続が必要）。既定のPDF関連付けを変更しません。検索には[公式の-searchオプション](https://www.sumatrapdfreader.org/docs/Command-line-arguments)を使います。生成資料・専用リーダーは測定ごとの `.desktop` フォルダーに保存されます。

通し動作確認は `.\.venv\Scripts\python.exe tests/manual_auto_check.py` で実行できます。試験用の一時フォルダーでOffice操作・PDF検索要求・動画・地図・WebRTCの進行と停止を検証します。

実Teamsを評価する場合は、従来の「デスクトップ併用テスト」を使用してください。そこでは会議参加と画面共有は手動です。

## デスクトップ併用テスト（Windows）

画面上部の「デスクトップ併用テスト」から、普段使う大きめの `.xlsx` と画像の多い `.pptx`、2〜5個の `.pdf` の絶対パスを入力し、「資料とブラウザー負荷を開始」を押します。Excel・PowerPointのデスクトップ版と、Acrobat / Acrobat Reader / SumatraPDFのいずれかが必要です。Teamsデスクトップ版は別途導入・サインインしてください。

- 自動：開始時の10秒測定後、Office資料を測定ごとの `.desktop` フォルダーにコピー。Excelは先頭シートの使用範囲を先頭列で昇順・降順に並べ替え（1行目を見出しとして扱う）、全再計算します。PowerPointは先頭スライドに試験文字を追加・移動し、スライド切り替えとコピーの保存を繰り返します。元資料は変更しません。保護・結合セル・暗号化などにより操作できない資料はエラーとして扱います。
- 自動：PDFをデスクトップリーダーで開き、Teamsクライアントの起動を要求。ブラウザー2タブの1080p動画・架空地図の経路再検索を約10分継続します。このモードでは模擬WebRTC会議を動かしません。
- 手動：PDFでCtrl+Fから同じ語を検索し、「PDF検索中」を選択。Teamsで試験会議に参加したら「Teams通話中」、資料を共有したら「画面共有中」を選択します。参加・共有・検索が実際に行われたことは自動検出しません。Officeの自動操作が続くため、操作するなら試験コピーを対象にしてください。
- 記録：既存CSVにExcel・PowerPoint・PDFのRSS推定を追加し、画面の段階別比較にも表示します。プロセス名による合算で、既存の資料を開いたプロセスも含みます。共有メモリや補助プロセスの扱いから、システム使用量との単純な足し算はできません。Officeの操作時間は `.desktop/operations.jsonl`、状態は `status.json`、エラー詳細は `worker.log` に保存します。
- 停止：「緊急停止」、空きメモリ下限、時間上限で終了します。Officeは処理中のCOM呼び出しが戻ってからコピーを閉じるため、即時停止できない場合があります。その場合は画面に終了待ちと表示します。元から開いていたPowerPoint全体を終了しません。PDFとTeamsは手動で閉じてください。会議・PDFが残るため、回復段階もそれらを含む値です。

Teamsが開かない場合もOffice・ブラウザーは実行されます。Teamsは手動で開いて参加してください。会議相手・ネットワーク・共有対象を固定し、操作時間は `operation-record.csv` に記録します。実際の参加者への連絡や会議参加・共有は自動実行しません。

Officeの動作確認は `.\.venv\Scripts\python.exe tests/manual_desktop_check.py`（試験ファイルを生成して2回操作）。対象の8GB PCではまず短時間で確認してください。

## 8GB PCでの実用限界調査

[実施手順](PRACTICAL_TEST.md)に従って、実際のPDF・表計算・5/10/20/30タブ・会議・画面共有を段階的に追加します。「設定・手動操作」から記録段階を切り替え、操作時間は `operation-record.csv` のコピーに記録してください。対象PCへコピーする際は `.venv` を除き、対象PCで以下の手順により仮想環境を作成します。手動測定だけならChromiumの追加セットアップは不要です。

搭載メモリは対象PCで確認してください。画面と測定CSVの `total_mib` はOS認識メモリです。メモリ容量の異なるPCでの結果は8GB実機の限界判定には使用しません。

ブラウザのタブ追加 → Microsoft Teams通話 → カメラON の各段階でメモリを比較する、日本語のローカルPythonアプリです。

## 起動

Python 3.9以上を使用します。

WindowsのPowerShellで、このフォルダーを開いて実行してください。

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

仮想環境内のPythonを直接使うため、Activate.ps1の実行や実行ポリシーの変更は不要です。2回目以降は最後の起動コマンドだけ実行します。
既定ブラウザに http://127.0.0.1:8765 が開きます。終了はターミナルで Ctrl+C。
ポート変更は `.\.venv\Scripts\python.exe app.py --port 8766`、自動ブラウザ起動を省略する場合は `--no-browser`、保存先は `--output PATH` で指定できます。

## 測定手順

1. 測定画面を開いた状態で「測定を開始」。開始時の状態を60秒程度記録します。
2. テスト対象URLを1行ずつ入力して「指定したタブを開く」。読み込み後に「2. タブ追加後」を選び、60秒程度記録します。
3. Teamsの会議URLを入力し「Teamsを開く」。自分でサインインし、カメラOFFで会議に参加した後「3. Teams通話中」を選びます。
4. Teams側でカメラをオンにした後「4. カメラON」を選び、同じ時間だけ記録します。
5. 「停止・保存」で終了し、段階別の平均・最大・開始時との差を比較します。CSVは `measurements/` に毎秒追記され、画面からもダウンロードできます。

新しい測定を開始すると画面上の比較はリセットされますが、過去のCSVは残ります。同じ段階を再選択すると、その段階のサンプルを合算します。ブラウザの再読み込みでは測定は止まりません。タブや通話の終了は手動です。

## 測定値の意味と比較上の注意

- システム使用量: `psutil.virtual_memory().total - available`。単位はMiB（1,048,576バイト）。OSのアクティビティモニタ等とは定義が異なる場合があります。
- ブラウザ・Teams: プロセス名で分類したRSSの合計。共有メモリは重複計上され、名称によって補助プロセスを見逃すことがあります。精密なアプリ別物理メモリ量ではありません。ゼロは該当する読み取り可能プロセスがない場合も意味します。
- 対象ブラウザ: Chrome / Chromium / Edge / Firefox / Safari / WebKit。全対象ブラウザの合計です。Safariの推定には他アプリのWebKitプロセスが含まれることがあります。
- Teams Web版はブラウザ側に含まれます。デスクトップ版の「teams」を含むプロセス名はTeams側に分類します。
- CPUはシステム全体の区間使用率。Swapはその時点の使用量。読取不可プロセス数も記録します。
- 1秒間隔を目標に収集しますが、収集時間やOSの負荷により間隔は延びます。サンプル数は秒数ではありません。CSVの時刻・elapsed_sで確認してください。
- この画面とPython自身、既存タブ、バックグラウンドアプリもシステム使用量に含まれます。前後差だけでTeamsの因果的な使用量を断定せず、同じタブ・会議人数・測定時間で繰り返して比較してください。
- 通話参加、カメラ、タブ数を自動検出しません。段階切り替えまでの操作中の値は直前の段階に含まれます。安定時だけを比べる場合はCSVの経過時間で対象区間を絞ってください。

サーバーは127.0.0.1でのみ待ち受けます。会議URLはメモリ計測CSVに保存しません。録音・録画や外部への測定データ送信はありません。指定URLを開くと、そのサイトへの通常のアクセスは発生します。

メモリ取得API: [psutil公式ドキュメント](https://psutil.io/)。

## 全自動ブラウザ負荷テスト

全自動テストは複数タブを並行作成し、全タブのページ読み込みも並行して開始します。手動の「指定したタブを開く」も起動要求を並行して送ります。実際の開始時刻にはOS・ブラウザーによる差があり、厳密な同時刻は保証しません。模擬業務の操作時間測定では、引き続き対象タブを順に前面へ切り替えます。

追加セットアップ（初回のみ）:

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
```

画面上部の「全自動テストを開始」で、専用Chromiumの起動、開始時測定、複数タブ作成、段階的なメモリ確保とCPU負荷、ブラウザ終了、回復測定、CSV保存まで実行します。テストは外部サイトにアクセスせず、同梱のローカル負荷ページを使います。既存ブラウザのタブやプロファイルは変更しません。

| プリセット | タブ | 1タブのメモリ上限 | CPU Worker合計上限 | Workerの稼働割合 | 各段階 |
|---|---:|---:|---:|---:|---:|
| 動作確認 | 2 | 16 MiB | 1 | 20% | 3秒 |
| 標準 | 6 | 96 MiB | 2 | 55% | 30秒 |
| 高負荷（既定） | 12 | 192 MiB | 8 | 90% | 45秒 |

CPU Worker数は論理CPU数−1まで（最低1）。割合は各Workerの100ms周期における計算時間の目標で、PC全体のCPU使用率ではありません。高負荷は操作のかくつきを狙う設定ですが、性能やOSのスケジューリングによって発生しない場合があります。

メモリ確保の合計は最大2 GiB、かつ「開始時の使用可能メモリ − 予約量」の50%以内。予約量は768 MiBと総メモリの10%の大きい方です。ブラウザ自身のメモリはこの確保量に加わります。予約量を下回った場合や5分経過で中断します。チェックは通常250msごとですが、ブラウザ操作中やPCの応答低下で遅れる場合があります。負荷ページにも最長90秒の停止タイマーがあります。

「緊急停止・負荷解放」で専用ブラウザを終了して取得済みCSVを残します。停止処理中は次の実行を開始できません。設定・完了理由・集計はCSVと同名のJSONにも保存します。高負荷実行前に編集内容を保存しておいてください。

Teamsの実際の会議参加とカメラ操作は引き続き手動です。全自動モードはブラウザ負荷テストを対象とし、Teams通話の再現や品質評価ではありません。

## 模擬業務シナリオ（約5分）

「模擬業務」を選び全自動テストを開始します。開始時30秒 → 資料を開いて30秒 → 映像OFFで表操作30秒 → 映像ONで複合作業150秒 → 専用ブラウザ終了後30秒。準備時間が加わり、全体の上限は6分です。

4タブを並行して開き、それぞれに20万行の売上データと24枚の1920×1080 Canvas資料を保持します。複合負荷段階では、同梱の生成済み1080p VP8動画をループ再生し、160×160の架空道路網で幅優先探索による経路再検索を約500msごとに行います。さらに12人の図形を合成した720p映像を、ローカルWebRTC接続で圧縮・送信・受信・復号します。4タブすべてでこれらを並行実行しながら、前面タブで表編集・検索・並べ替え・資料スクロールを繰り返します。

実際のPDF、外部地図サービス、Teams、カメラ、音声、WAN通信は再現しません。WebRTCは1タブにつき1本の合成映像で、12本の映像ではありません。同時負荷を維持するため専用Chromiumのバックグラウンドタイマー抑制などを無効化しており、通常ブラウザーより厳しい条件です。従来の模擬業務とは負荷条件が異なるため、過去結果と同条件の比較はできません。

`.latency.jsonl`には動画の再生・ドロップフレーム数、経路検索回数・処理時間、WebRTC復号フレーム数も記録します。動画はローカル生成した短い試験映像で、実写映像の圧縮特性とは異なります。

ブラウザーで複合負荷の確認を行う場合は `.\.venv\Scripts\python.exe tests/manual_workload_check.py` を実行します。4タブの各処理が進むことと停止時のリソース解放を確認します。

操作の計算時間と、2回のrequestAnimationFrameまでの経過時間（描画待ち込みの近似応答時間）を `.latency.jsonl` に逐次保存します。後者は画面が実際に表示された瞬間の厳密な計測ではありません。映像OFF/ONで同じ操作を比較し、平均・p95・最大をJSONおよびダッシュボードに表示します。実際のOS全体の操作遅延やTeams通話品質は測定しません。

模擬業務は実データ構造・描画用メモリを使用するため、合成負荷用のMiB設定は適用しません。空きメモリ下限での自動停止は共通です。安全停止や操作タイムアウト時もCSVと取得済みJSONLは残ります。

ダッシュボードは画面高に合わせて主要指標・グラフ・比較表を配置します。狭い画面では比較表内のみスクロール可能です。手動操作は「設定・手動操作」から開けます。
