# Memory Lab

ブラウザのタブ追加 → Microsoft Teams通話 → カメラON の各段階でメモリを比較する、日本語のローカルPythonアプリです。

## 起動

Python 3.9以上を使用します。

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

Windowsでは仮想環境の有効化に `.venv\Scripts\activate` を使ってください。
既定ブラウザに http://127.0.0.1:8765 が開きます。終了はターミナルで Ctrl+C。
ポート変更は `python app.py --port 8766`、自動ブラウザ起動を省略する場合は `--no-browser`、保存先は `--output PATH` で指定できます。

## 測定手順

1. 測定画面を開いた状態で「測定を開始」。開始時の状態を60秒程度記録します。
2. テスト対象URLを1行ずつ入力して「指定したタブを開く」。読み込み後に「2. タブ追加後」を選び、60秒程度記録します。
3. Teamsの会議URLを入力し「Teamsを開く」。自分でサインインし、カメラOFFで会議に参加した後「3. Teams通話中」を選びます。
4. Teams側でカメラをオンにした後「4. カメラON」を選び、同じ時間だけ記録します。
5. 「停止・保存」で終了し、段階別の平均・最大・開始時との差を比較します。CSVは `measurements/` に毎秒追記され、画面からもダウンロードできます。

新しい測定を開始すると画面上の比較はリセットされますが、過去のCSVは残ります。同じ段階を再選択すると、その段階のサンプルを合算します。ブラウザの再読み込みでは測定は止まりません。タブや通話の終了は手動です。

## 測定値の意味と比較上の注意

- システム使用量: `psutil.virtual_memory().total - available`。単位はMiB（1,048,576バイト）。OSのアクティビティモニタ等とは定義が異なる場合があります。
- ブラウザ・Teams: プロセス名で分類したRSSの合計。共有メモリは重複計上され、名称によって補助プロセスを見逃すことがあります。精密なアプリ別物理メモリ量ではありません。ゼロは該当する読み取り可能プロセスがない場合も意味します。
- 対象ブラウザ: Chrome / Chromium / Edge / Firefox / Safari / WebKit。全対象ブラウザの合計です。Safariの推定には他アプリのWebKitプロセスが含まれることがあります。
- Teams Web版はブラウザ側に含まれます。デスクトップ版の「teams」を含むプロセス名はTeams側に分類します。
- CPUはシステム全体の区間使用率。Swapはその時点の使用量。読取不可プロセス数も記録します。
- 1秒間隔を目標に収集しますが、収集時間やOSの負荷により間隔は延びます。サンプル数は秒数ではありません。CSVの時刻・elapsed_sで確認してください。
- この画面とPython自身、既存タブ、バックグラウンドアプリもシステム使用量に含まれます。前後差だけでTeamsの因果的な使用量を断定せず、同じタブ・会議人数・測定時間で繰り返して比較してください。
- 通話参加、カメラ、タブ数を自動検出しません。段階切り替えまでの操作中の値は直前の段階に含まれます。安定時だけを比べる場合はCSVの経過時間で対象区間を絞ってください。

サーバーは127.0.0.1でのみ待ち受けます。会議URLはメモリ計測CSVに保存しません。録音・録画や外部への測定データ送信はありません。指定URLを開くと、そのサイトへの通常のアクセスは発生します。

メモリ取得API: [psutil公式ドキュメント](https://psutil.io/)。

## 全自動ブラウザ負荷テスト

追加セットアップ（初回のみ）:

```sh
pip install -r requirements.txt
python -m playwright install chromium
```

画面上部の「全自動テストを開始」で、専用Chromiumの起動、開始時測定、複数タブ作成、段階的なメモリ確保とCPU負荷、ブラウザ終了、回復測定、CSV保存まで実行します。テストは外部サイトにアクセスせず、同梱のローカル負荷ページを使います。既存ブラウザのタブやプロファイルは変更しません。

| プリセット | タブ | 1タブのメモリ上限 | CPU Worker合計上限 | Workerの稼働割合 | 各段階 |
|---|---:|---:|---:|---:|---:|
| 動作確認 | 2 | 16 MiB | 1 | 20% | 3秒 |
| 標準 | 6 | 96 MiB | 2 | 55% | 30秒 |
| 高負荷（既定） | 12 | 192 MiB | 8 | 90% | 45秒 |

CPU Worker数は論理CPU数−1まで（最低1）。割合は各Workerの100ms周期における計算時間の目標で、PC全体のCPU使用率ではありません。高負荷は操作のかくつきを狙う設定ですが、性能やOSのスケジューリングによって発生しない場合があります。

メモリ確保の合計は最大2 GiB、かつ「開始時の使用可能メモリ − 予約量」の50%以内。予約量は768 MiBと総メモリの10%の大きい方です。ブラウザ自身のメモリはこの確保量に加わります。予約量を下回った場合や5分経過で中断します。チェックは通常250msごとですが、ブラウザ操作中やPCの応答低下で遅れる場合があります。負荷ページにも最長90秒の停止タイマーがあります。

「緊急停止・負荷解放」で専用ブラウザを終了して取得済みCSVを残します。停止処理中は次の実行を開始できません。設定・完了理由・集計はCSVと同名のJSONにも保存します。高負荷実行前に編集内容を保存しておいてください。

Teamsの実際の会議参加とカメラ操作は引き続き手動です。全自動モードはブラウザ負荷テストを対象とし、Teams通話の再現や品質評価ではありません。

## 模擬業務シナリオ（約5分）

「模擬業務」を選び全自動テストを開始します。開始時30秒 → 資料を開いて30秒 → 映像OFFで表操作30秒 → 映像ONで複合作業150秒 → 専用ブラウザ終了後30秒。準備時間が加わり、全体の上限は6分です。

4タブそれぞれに20万行の売上データと12枚のCanvas資料を作成します。タブを順に前面へ切り替え、セル値更新・検索・並べ替え・集計・1,200行のDOM更新・表と資料のスクロールを繰り返します。映像ONでは各タブで1280×720の12人分の模擬映像をCanvasからMediaStreamとしてVideo要素へ渡します。ネットワーク通信、映像コーデックによる圧縮、実際の会議やカメラ処理を再現するものではありません。

操作の計算時間と、2回のrequestAnimationFrameまでの経過時間（描画待ち込みの近似応答時間）を `.latency.jsonl` に逐次保存します。後者は画面が実際に表示された瞬間の厳密な計測ではありません。映像OFF/ONで同じ操作を比較し、平均・p95・最大をJSONおよびダッシュボードに表示します。実際のOS全体の操作遅延やTeams通話品質は測定しません。

模擬業務は実データ構造・描画用メモリを使用するため、合成負荷用のMiB設定は適用しません。空きメモリ下限での自動停止は共通です。安全停止や操作タイムアウト時もCSVと取得済みJSONLは残ります。

ダッシュボードは画面高に合わせて主要指標・グラフ・比較表を配置します。狭い画面では比較表内のみスクロール可能です。手動操作は「設定・手動操作」から開けます。
